# Routin 每日签到设计

## 目标

在 MyRoutin 中提供一个明确的“签到”操作：用户点击一次即可使用其 Routin 官方网页登录会话进入每日签到页并完成签到。应用不收集、不保存 Routin 账号密码、验证码或手工导出的 Cookie。

## 方案

### 登录会话

- 新增独立的 `RoutinWebSession`，以 `WKWebView` 承载 `https://routin.ai` 的官方登录与签到页面。
- 首次使用或会话失效时，应用展示 Routin 官方登录页；用户在该页面自行完成登录。
- WebKit 网站数据存储在 macOS 的应用容器内，由系统管理；应用不读取、序列化或显示 Cookie 内容。
- 设置页新增“Routin 签到”区域，仅展示已登录、未登录或需要重新登录状态，并提供“登录 Routin”“重新登录”和“退出登录”操作。
- 退出登录仅清除 `routin.ai` 对应的网站数据，不影响现有 plan Key 和用量缓存。

### 签到入口与流程

- 用量弹窗新增图标式“签到”入口；设置页的 Routin 签到区域提供同一操作。
- 用户触发签到后，应用加载 `https://routin.ai/dashboard/lottery`。
- 若网页会话有效，则加载签到页，并由页面桥接或页面状态识别判断签到结果。
- 若被重定向至登录页、显示未认证页面或无法识别登录态，则显示登录窗口；登录完成后自动返回签到页并继续本次操作。
- 对网页可直接调用的签到动作使用受限 JavaScript 桥接；不猜测或硬编码未验证的私有 HTTP 接口、Cookie 或 CSRF 参数。

### 状态与错误反馈

- 按钮在进行中显示不可重复触发的加载状态。
- 成功后展示“签到成功”；若页面明确表明当天已完成，则展示“今天已签到”。
- 未登录或会话失效时展示“请先登录 Routin”，并提供重新登录路径。
- 网络、页面加载或页面结构变化导致无法确认结果时展示“无法确认签到结果，请在 Routin 页面中检查”，同时保留打开该页面的能力。
- 不将网页 HTML、Cookie、账号标识或响应正文写入诊断日志。

## 组件边界

- `RoutinWebSession`：创建和持有受限 WebKit 配置，加载登录页和签到页，判断会话与签到结果，清除站点数据。
- `RoutinCheckInService`：面向界面提供登录、签到、登出和状态查询，串行化重复操作并生成用户可见的结果状态。
- `RoutinCheckInWindow`：仅在需要授权或需要用户查看网页时显示；负责 WebView 展示和关闭回调。
- `RoutinCheckInState`：表示未登录、登录中、已登录、签到中、签到成功、今日已签到及可恢复错误。
- `SettingsView` 和 `UsagePopoverView`：只消费服务状态并触发命令，不直接处理 WebKit 或网站数据。

## 数据流

1. 用户在弹窗或设置页点击签到。
2. `RoutinCheckInService` 检查 WebKit 会话可用性并进入签到中状态。
3. 会话无效时，`RoutinCheckInWindow` 打开官方登录页；用户完成登录后服务恢复本次签到。
4. 服务加载每日签到页，等待页面加载完成并尝试执行经验证的页面动作或读取明确结果。
5. 服务更新 `RoutinCheckInState`，两个入口同步显示最终结果。

## 安全与兼容性

- 不增加用户名、密码、验证码、Token 或 Cookie 的设置项。
- 不使用 `UserDefaults` 保存网页登录凭据；现有 `LocalKeyStore` 也不承载网页登录会话。
- 仅允许 WebView 导航至 `https://routin.ai` 及登录流程实际需要的、经审核的身份提供商域名；所有外部链接交给默认浏览器。
- JavaScript 桥接仅用于已加载的目标页，避免接受网页传入的任意命令。
- Routin 页面结构或站点策略变化时，应用必须安全失败：不伪造成功、不暴露会话数据，并引导用户打开官方页面确认。

## 验收标准

- 未登录用户点击签到后可在应用内完成 Routin 官方登录，无需输入或保存账号密码到应用设置。
- 登录成功后，本次签到会自动继续；后续点击签到可复用会话。
- 用户可以在设置页看到登录状态并主动退出登录；退出不影响现有 Key、用量和其他设置。
- 签到中不会重复提交；成功、已签到、登录失效、网络失败和无法确认结果均有清晰提示。
- 自动化测试覆盖状态转换、重复点击保护、登录重试、登出网站数据范围和页面结果解析；并运行现有完整测试套件。

## 待验证的外部契约

- Routin 登录重定向涉及的实际身份提供商域名。
- 每日签到页的可访问状态、可点击元素与成功/已签到文案或 DOM 标识。
- 是否存在稳定、公开且允许客户端调用的签到接口。若不存在，不实现接口仿真，保留官方页面驱动流程。
