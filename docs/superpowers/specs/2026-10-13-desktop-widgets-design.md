# 桌面小组件重做设计摘要

## 目标

为 MyToken 建立一套跨 macOS 与 Android 的桌面小组件体验：提供“总览”和“单凭证”两类组件，支持“自动 / 聚焦环 / 扫描带 / 信号格”四种视觉风格。组件内容根据每个凭证本次快照实际存在的归一化指标动态生成，不同供应商和不同套餐可以显示不同指标。

## 产品结构

### 组件类型

- **MyToken 总览**：默认聚合全部启用凭证，按风险优先和用户排序显示前 N 个；可切换为手动选择凭证，最多 6 个。
- **MyToken 凭证**：绑定一个凭证；主指标默认自动选择，也允许用户固定。

### 视觉风格

用户可选择：

- `自动`
- `聚焦环`
- `扫描带`
- `信号格`

默认 `自动`。自动规则：

- 紧凑尺寸：A1 上信息、中环、下指标。
- 标准单凭证：A2 左环、右摘要。
- 标准总览：扫描带。
- 扩展单凭证：信号格。
- 扩展总览：扫描带加风险摘要。

所有标题、指标名、数值和时间均为单行显示；空间不足时用省略号截断标题与指标名，不允许换行、重叠或溢出。

### 尺寸矩阵

| 抽象尺寸 | 指标数量 | macOS | Android |
| --- | --- | --- | --- |
| 紧凑 | 单凭证 1 主指标 + 1 摘要 | `systemSmall` | 约 2x2 / 2x3 |
| 标准 | 单凭证最多 4 指标；总览最多 3 凭证 | `systemMedium` | 约 4x2 / 5x2 |
| 扩展 | 单凭证最多 6 指标；总览最多 5-6 凭证 | `systemLarge` | 约 4x3、4x4、5x4 |

Android 不按机型或折叠状态判断尺寸，而是读取小组件实际可用宽高，用统一阈值映射到三档抽象尺寸。

## 架构

### macOS

- 新增 WidgetKit extension。
- 主应用仍是唯一读取凭证并请求供应商的进程。
- 刷新完成后生成不含密钥的 `WidgetSnapshotBundle v1`，原子写入 App Group 共享容器。
- WidgetKit extension 只读共享快照，不访问 API Key、Cookie、Key 后缀或原始凭证。
- 主应用调用 `WidgetCenter.reloadAllTimelines()`。
- 点击组件打开主应用对应凭证详情并触发刷新。
- Timeline 为重置时间、订阅到期时间和缓存过期时间生成后续 entry，只更新时间类信息，不伪造新的用量数据。

### Android

- 渲染层改用 Glance，继续复用 Room 缓存、供应商刷新用例和 WorkManager。
- 新增纯 Kotlin `WidgetPresentationBuilder`，把凭证、快照、配置、风格和尺寸转换为渲染模型。
- 保留现有全局周期 `RefreshWorker`，不新增第二套周期刷新。
- 手动刷新改为全局唯一一次性任务，刷新所有已安装小组件需要的凭证并集。
- 增加按凭证合并 in-flight 请求，避免组件手动刷新、后台刷新和前台刷新并发时重复请求上游。
- 现有 `credential_<widgetId>` 配置迁移到 v2，保留单凭证选择，并新增组件类型、风格、总览来源和主指标配置。

## 指标选择

两端实现一致的 `WidgetMetricRanker`：

1. 用户固定主指标优先。
2. 未固定时选择供应商稳定主指标，不因单次用量变高而频繁切换。
3. 次要指标按语义去重和供应商顺序选择。
4. 总览排序按风险优先：认证失败、指标不可用、即将过期、高占用、低余额，然后回到用户排序。
5. 供应商语义保留：Command Code 保持五小时、周额度、购买/免费余额顺序；NewAPI 配对 Token 与费用；Xiaomi 保持命中/未命中缓存顺序和完整分组数字。
6. 固定指标不存在时显示“该指标暂不可用”，其它真实可用指标继续显示。

## 状态与降级

- 无凭证：显示“打开应用添加凭证”。
- 首次加载：显示骨架和“正在获取”，不显示假 0%。
- 失败但有缓存：显示上次成功数据、失败分类和更新时间。
- 认证失败：显示“需要重新登录/更换凭证”。
- 凭证停用：降低不透明度并显示“已停用 · 显示缓存”。
- 凭证删除：单凭证组件提示重新配置；总览自动移除。
- 无可用指标：显示“该套餐暂无可用指标”。
- 数据过期：用时间徽标表达，不用红色伪装成高占用。

## 配置

- macOS 使用 WidgetKit/AppIntent 原生配置界面。
- Android 重做现有配置 Activity：顶部实时预览，下方配置凭证、风格、主指标和总览来源。
- 配置项限制为：组件类型、视觉风格、单凭证主指标、总览凭证来源。
- 次要指标始终自动选择。

## 验收

- 同一组跨端 fixture 验证供应商主指标、次要指标、格式和排序一致。
- App Group 快照与 Android 渲染输入不得包含 secret、Cookie、Key 后缀。
- 并发刷新时同一凭证只允许触发一次上游请求。
- 三档尺寸、深浅色、长名称、长套餐、大数字、多供应商指标不换行、不重叠、不溢出。
- 覆盖无凭证、首次加载、失败有缓存、认证失败、停用、删除、固定指标缺失和数据过期。
- macOS 运行 `scripts/test.sh`，构建 Release DMG，并在真实桌面添加 Small/Medium/Large 组件验证。
- Android 运行 `./android/gradlew -p android test`，构建 Release 包并安装到真实设备或模拟器验证尺寸和深浅色。
