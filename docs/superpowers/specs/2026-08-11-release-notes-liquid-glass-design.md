# MyRoutin 发布更新日志、定时更新检查与液态玻璃设计

## 目标

让每次手动发布都必须附带 Markdown 更新日志；应用在设置页清晰显示当前版本、可用新版本及完整更新日志，并在启动后每六小时自动检查一次。整体视觉采用明亮通透的 macOS 液态玻璃风格，同时重排菜单栏弹窗的用量信息以减少垂直空间。

## 范围与约束

- 发布仅由 GitHub Actions 的 `workflow_dispatch` 手动触发。
- 发布者必须粘贴完整 Markdown 更新日志；不再使用 GitHub 自动生成发布说明。
- 应用的最低部署版本保持 macOS 14；macOS 26 及以上使用原生液态玻璃能力，macOS 14–25 使用安全的材质降级效果。
- 更新检查在应用启动时执行一次，随后每六小时执行一次；不得阻塞用量刷新、通知授权或菜单栏首次显示。
- 仅显示 GitHub 最新正式 Release 的正文，继续使用现有 DMG 下载与自动安装流程。
- 菜单栏弹窗不显示模型清单；所有已有 Key、用量、通知、设置窗口可调整大小等行为保持不变。

## 发布工作流

`release.yml` 保留版本号输入，新增或重命名为必填的 `release_notes` 字符串输入，提示发布者粘贴 Markdown。构建步骤继续将输入版本写入 `MARKETING_VERSION` 并产出 `MyRoutin.dmg`。

创建 Release 时：

- 标签：`v<version>`。
- 标题：`MyRoutin v<version>`。
- 正文：`release_notes` 的原文，不做转义或截断。
- `generate_release_notes` 固定为 `false`，防止空文本或 GitHub 自动说明覆盖人工日志。

工作流仍只在 GitHub 托管 macOS 上运行，不引入第三方发布凭证。

## 更新模型与检查调度

现有 `AppUpdate` 保持 `version`、`releaseURL`、`downloadURL` 与 `notes` 字段。`GitHubUpdateService` 继续从 GitHub Release API 解析 `body` 到 `notes`，并保留版本比较、DMG 资产选择和错误映射。

`AppEnvironment` 新增一个可取消的更新检查任务：

1. 启动阶段在后台立即调用 `checkForUpdates()`。
2. 启动成功后创建循环任务，每 6 小时再次调用；任务之间使用可取消的 `Task.sleep`。
3. `stop()`、应用终止和环境释放时取消任务，避免停止后的网络请求或泄漏。
4. 手动“检查更新”继续可用，且现有“正在检查/下载”互斥保护不变。

检查失败只更新“软件更新”区域的状态，不影响菜单栏用量、刷新调度或已发现的新版本；如果已有可安装版本且后台检查失败，保留该版本信息，避免丢失用户可见的更新入口。

## 设置页的软件更新区域

“软件更新”区域按以下优先级呈现：

1. 始终显示 `当前版本 <CFBundleShortVersionString>`；无法读取时显示 `当前版本 —`。
2. 检查中显示紧凑的进度指示器，当前版本不消失。
3. 发现更新时显示 `发现新版本 <version>`、完整 Markdown 富文本更新日志、安装更新按钮和 GitHub 发布页面链接。
4. Release 正文为空时显示“此版本未提供更新日志”。
5. 下载/安装中显示进度状态；失败时显示错误和重试按钮。

Markdown 由 SwiftUI 的 `AttributedString(markdown:)` 解析。解析失败时回退为原始纯文本，确保来自 GitHub 的任何日志都可读。更新日志放在检测结果下方，允许按内容自然撑开，不再限制为三行。

菜单栏弹窗只保留“发现新版本”和安装操作，避免展开日志挤占用量信息；完整日志仅在设置页显示。

## 液态玻璃视觉系统

选定视觉方向为“明亮通透”：带有柔和高光边缘、背景材质模糊和分层卡片，但用量数值、进度条和操作文字始终保持可读。

新增一个集中管理视觉材质的 SwiftUI 辅助层：

- macOS 26+：使用系统提供的液态玻璃/玻璃容器修饰符，避免手工仿制系统的交互与动态效果。
- macOS 14–25：使用 `.regularMaterial`/`.thinMaterial`、圆角、半透明描边和阴影实现同层级的兼容版本。
- 窗口内的 Tab、列表行、统计卡片、弹窗工具栏与软件更新区域使用统一的玻璃表面修饰符；按钮仍使用系统标准样式，破坏性操作不降低警示色。
- 菜单栏标签保持原生单色图像渲染与当前尺寸，不将玻璃背景绘制到系统菜单栏中。
- 设置窗口的 Tab、分区、列表行、开关、Picker、按钮和进度条均接入统一玻璃外观，且保留系统语义、键盘操作与危险操作颜色。
- “别名 + 竖形进度条”不再将别名和竖条烘焙为一张图片：别名使用原生菜单栏文字，让系统按实际菜单栏背景自动选择白色或黑色；彩色竖条作为独立非模板图像保留绿/黄/红风险色，不读取或分析壁纸像素。

所有系统新 API 必须置于 `if #available(macOS 26.0, *)` 分支；编译器无法识别的 API 需用可用 SDK 对应写法并提供 macOS 14–25 回退分支，不能提高项目部署目标。

## 菜单栏弹窗布局

对有周期套餐的 `UsageRowView`：

1. 标题、百分比、进度条与金额行保持不变。
2. 分组倍率移至进度条/金额信息之后，单独一行并右对齐，例如 `Codex ×1 · Codex Pro ×2`。
3. “5 小时剩余”和“周剩余”放入同一个横向容器；前者左对齐，后者右对齐。没有窗口结束时间时各自显示 `—`。
4. `TimelineView` 仍每分钟更新剩余时长；辅助功能标签包含两个倒计时与分组倍率。

Token 资源包不显示周期倒计时，分组倍率仍按可用数据显示。

## 测试与验收

- 发布工作流静态测试：日志输入为必填、Release 正文取该输入、自动说明被禁用、标题继续使用 `MyRoutin`。
- GitHub 更新服务测试：保留 Markdown 原文和空正文；版本不更新时不提示。
- 应用生命周期测试：启动立即检查、6 小时后再次检查、停止后取消调度；后台失败不覆盖已有可用更新。
- 设置页静态/视图测试：显示当前版本、完整更新日志、空日志提示、Markdown 回退文本及安装/链接操作。
- 弹窗布局测试：分组倍率使用右对齐容器，两个剩余时长在同一横向容器，倒计时格式保持既有规则。
- 运行完整 `scripts/test.sh`，并按现有脚本验证无测试偏好 plist 与临时构建目录残留。
