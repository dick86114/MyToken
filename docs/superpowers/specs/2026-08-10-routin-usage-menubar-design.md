# Routin 用量菜单栏应用设计规格

## 1. 项目概述

本项目是一款供少量用户私下使用的原生 macOS 菜单栏应用，用于通过 Routin 订阅用量接口持续监控多个 plan Key 的额度使用情况。

应用以菜单栏百分比提供低干扰的实时反馈；点击后可在紧凑面板中查看全部 Key，并通过进度条快速识别额度风险。应用同时支持周期订阅和 Token 资源包，提供自动刷新、离线缓存、阈值通知、登录时启动和独立设置窗口。

应用不公开发布、不上架 App Store，也不建设账号体系、遥测或商业化能力。

## 2. 已确认的产品约束

- API 地址固定为 `https://api.routin.ai/plan/v1/usage`。
- 每条监控配置仅要求用户填写“显示名称 + plan Key”。
- 支持配置和监控多个 Key。
- 菜单栏一次只展示用户选中的一个 Key。
- 菜单栏仅显示百分比，不显示 Key 名称，以节省空间。
- 接口中的 `daily*` 字段实际代表当前 5 小时额度窗口，界面统一显示为“5 小时”。
- 周期订阅支持“5 小时 / 周”显示维度切换。
- Token 资源包固定显示总 Token 额度使用率。
- 默认每 5 分钟刷新，可选 1、5、15、30 分钟，并支持手动刷新。
- 应用使用独立设置窗口，默认不显示 Dock 图标。
- 应用支持额度预警和登录时启动。
- 采用原生 SwiftUI 实现，最低目标系统为 macOS 14；必要时只对局部系统能力使用 AppKit。
- 通过未签名 `.app` 和 `.dmg` 私下分发，用户首次运行时自行在系统设置中允许打开。

## 3. 首版功能范围

### 3.1 包含的功能

- 添加、编辑、删除和排序多个 Key。
- 将真实 Key 安全存储在 macOS Keychain。
- 选择一个 Key 作为菜单栏当前监控对象。
- 在菜单栏显示当前维度的整数使用率，例如 `68%`。
- 在展开面板中以紧凑列表显示全部 Key 的用量。
- 自动识别周期订阅和 Token 资源包。
- 周期订阅支持“5 小时 / 周”维度切换。
- 自动刷新、手动刷新、系统唤醒后补充刷新。
- 保存不含密钥的最后成功数据，用于离线展示。
- 对全部监控 Key 提供可配置阈值通知。
- 提供登录时启动开关。
- 提供独立设置窗口和首次启动引导。
- 生成未签名 `.app` 和 `.dmg`，并提供首次运行说明。

### 3.2 首版不包含的功能

- 历史趋势图和长期本地采样。
- 多设备同步。
- 配置导入和导出。
- 自动更新。
- App Store 发布、应用遥测和崩溃数据上传。
- 自定义 API 地址。
- 菜单栏轮播或同时展示多个 Key。

## 4. 用户体验设计

### 4.1 菜单栏

菜单栏默认只显示当前 Key 的整数使用率。周期订阅显示用户选中的“5 小时”或“周”使用率；资源包忽略周期选项，始终显示 Token 总额度使用率。

菜单栏使用系统文字颜色，以保证在不同壁纸、深浅模式和菜单栏状态下的可读性。Key 名称通过悬停提示和展开面板提供，不占用常驻空间。

没有可用数据时使用以下简短状态：

- 正在首次加载：`…`
- 当前 Key 无可用订阅：`--`
- 当前 Key 请求失败且没有缓存：`!`
- 存在缓存但本次刷新失败：继续显示缓存百分比，悬停提示中标记数据已过期。

### 4.2 紧凑总览面板

点击菜单栏百分比后打开紧凑总览面板。面板结构如下：

1. 顶部包含“5 小时 / 周”分段切换和手动刷新按钮。
2. 中部按用户设置的顺序列出全部 Key；Key 较多时在固定高度区域内滚动，顶部与底部操作区保持可见。
3. 每行显示名称、订阅类型、百分比、进度条、已用量、总额度或剩余额度，以及窗口结束时间。
4. 当前菜单栏 Key 使用实心状态标记，其他 Key 使用空心标记。
5. 点击任意 Key 行会将其设为菜单栏当前 Key。
6. Token 资源包行始终显示 Token 总额度，不受顶部周期切换影响。
7. 底部显示最近一次刷新时间、刷新状态和设置入口。

进度条风险颜色为：

- 低于 80%：绿色。
- 80% 至低于 95%：橙色。
- 95% 及以上：红色。
- 无法获取有效数据：灰色。

某个 Key 请求失败只影响对应行，其他 Key 继续正常更新。失败行优先展示最后成功数据和过期标识；没有缓存时展示简短错误状态与重试入口。

### 4.3 独立设置窗口

设置窗口包含以下区域：

- Key 管理：添加、编辑、删除、拖动排序。
- 显示设置：选择菜单栏当前 Key 和周期订阅默认维度。
- 刷新设置：选择 1、5、15、30 分钟自动刷新间隔。
- 通知设置：开关通知，并设置两个全局预警阈值，默认 80% 和 95%。
- 系统设置：开关登录时启动。

列表只显示脱敏后的 Key，例如 `plan-••••8F2A`。新增或编辑 Key 后立即调用接口验证；验证成功后保存。验证失败时保留编辑内容、显示明确原因并允许用户修改或重试，不把无效 Key 写入正式配置。

### 4.4 首次启动

首次启动打开简短引导和设置窗口，引导用户添加第一个 Key。成功添加后立即执行第一次刷新，随后关闭引导并进入常规菜单栏状态。

## 5. 技术架构

### 5.1 技术选型

- Swift 与 SwiftUI。
- `MenuBarExtra` 实现菜单栏入口和展开面板。
- SwiftUI `Settings` 或独立 `Window` 场景实现设置窗口。
- `URLSession` 发起 HTTPS 请求。
- Security/Keychain API 保存密钥。
- UserNotifications 发送系统通知。
- ServiceManagement 实现登录时启动。
- Swift Testing 或 XCTest 负责自动化测试。

若 SwiftUI 对某个菜单栏交互细节存在明确限制，仅对该能力局部使用 AppKit，不改变整体原生 SwiftUI 架构。

### 5.2 模块职责

#### KeyStore

管理 Key 的显示名称、排序、内部 UUID 和当前选中项。非敏感元数据存入应用偏好设置，真实 Key 交由 KeychainStore 保存。

#### KeychainStore

封装 Keychain 的新增、读取、更新和删除。外部模块只通过内部 UUID 获取密钥，不接触持久化细节。

#### UsageAPIClient

固定请求：

```http
GET https://api.routin.ai/plan/v1/usage
Authorization: Bearer <plan-key>
```

每个 Key 独立发起请求并返回原始响应模型或明确错误。客户端不得在日志中输出请求头、完整 Key 或完整响应体。

#### UsageMapper

将接口模型转换为统一界面模型。周期订阅和资源包映射到不同的额度结构，但向界面提供一致的百分比、已用量、总额度、剩余额度和状态接口。

`daily*` 保留为传输层字段名称，领域模型和界面文案使用“五小时窗口”，避免错误修改接口契约。

订阅类型优先根据实际有效额度字段判断，不完全依赖当前文档未解释枚举含义的 `type` 数字。若周期字段和 Token 字段同时有效，按接口 `type` 选择；若 `type` 无法识别，则优先选择具有非零总额度的一类，并记录不含敏感内容的兼容性诊断信息。

#### UsageStore

作为界面状态的单一来源，维护每个 Key 的最新数据、最后成功数据、更新时间、加载状态和错误。它协调请求、映射、缓存和通知，并在主线程发布界面状态。

#### RefreshScheduler

应用启动时立即刷新，之后按用户设置的间隔运行。系统从休眠恢复或网络恢复后，在避免重复请求的前提下补充刷新。手动刷新可立即触发，但同一个 Key 同一时刻只允许一个进行中的请求。

#### UsageCache

持久化每个 Key 最后一次成功的统一用量模型和时间戳。缓存不得包含真实 Key、Authorization 请求头或其他密钥材料。

#### AlertManager

评估全部 Key 的额度状态，负责阈值判断、去重和系统通知。通知状态以“Key 内部 UUID + 额度类型 + 窗口标识 + 阈值”作为唯一维度。

## 6. 数据模型与计算规则

### 6.1 周期订阅

- 5 小时使用率：`dailyUsedUsd / dailyLimitUsd × 100%`
- 周使用率：`weeklyUsedUsd / weeklyLimitUsd × 100%`
- 5 小时窗口结束时间：`dayWindowEndAt`
- 周窗口结束时间：`weekWindowEndAt`

虽然接口字段包含 `daily`，产品文案不得显示“日”或“每日”，统一显示“5 小时”。

### 6.2 Token 资源包

- Token 使用率：`consumedTokens / totalTokens × 100%`
- 剩余额度优先使用 `remainingTokens`；若字段缺失，则用 `totalTokens - consumedTokens` 计算。

### 6.3 边界规则

- 总额度大于零时才计算百分比。
- 总额度为零或字段不足时显示不可计算状态，不执行除零。
- 界面进度条限制在 0% 至 100%，但领域模型保留真实百分比，以正确处理超额和通知。
- 菜单栏百分比四舍五入为整数。
- 金额展示遵循接口单位 USD，并使用稳定的小数格式。
- Token 数量使用便于阅读的缩写格式，同时在悬停或详情中提供完整数值。

## 7. 刷新与并发流程

一次刷新流程如下：

1. RefreshScheduler 发出刷新事件。
2. UsageStore 获取全部已配置 Key。
3. UsageAPIClient 为每个 Key 发起相互独立的请求。
4. UsageMapper 将成功响应转换为统一模型。
5. UsageStore 逐个更新对应 Key 的状态，不等待全部请求成功后才更新界面。
6. 成功数据写入 UsageCache。
7. AlertManager 评估成功结果并按需发送通知。
8. 单个请求错误只写入对应 Key，不覆盖该 Key 的最后成功缓存。

自动刷新间隔默认 5 分钟，允许设置为 1、5、15、30 分钟。用户修改间隔后，调度器立即采用新配置并重新计算下一次刷新时间。

## 8. 错误处理

- 返回 `null`：显示“无可用订阅”。
- HTTP 401 或 `invalid_api_key`：显示“Key 无效”；已有缓存可继续展示，但必须明确标记无效状态。
- 网络中断或超时：展示最后成功缓存和过期标识；没有缓存时显示“网络错误”。
- 响应无法解析：展示“接口数据异常”，保留缓存并记录脱敏诊断信息。
- 部分字段缺失：尽量使用可用字段；无法安全计算时显示不可计算状态，不猜测额度。
- 全部 Key 请求失败：菜单栏仍根据当前 Key 的缓存决定显示百分比或错误符号，弹窗提供统一重试入口。

最后成功数据超过两倍自动刷新间隔即视为过期；刷新间隔为 1 分钟时，至少等待 5 分钟才标记过期，避免短暂调度延迟造成频繁状态变化。

## 9. 通知规则

- 默认阈值为 80% 和 95%，用户可全局修改。
- 两个阈值必须为 1% 至 100% 的整数，且低阈值必须小于高阈值。
- 监控全部 Key，而不仅是菜单栏当前 Key。
- 周期订阅分别评估 5 小时和周额度；资源包评估 Token 总额度。
- 同一 Key、同一额度类型、同一窗口、同一阈值只通知一次。
- 进入新的额度窗口后清除对应窗口的已通知状态。
- 一次刷新跨越多个阈值时只发送最高等级通知。
- 通知内容包含 Key 显示名称、额度类型、当前使用率和可用的窗口结束时间。
- 用户关闭通知时不请求或使用系统通知权限。

## 10. 安全与隐私

- 真实 Key 只存入 macOS Keychain。
- 偏好设置、缓存、日志、通知和界面均不得出现完整 Key。
- 所有接口请求固定使用 HTTPS。
- 删除 Key 时同步删除 Keychain 项、缓存和通知去重状态。
- 应用不采集遥测，不上传崩溃数据，不连接 Routin 用量接口之外的业务服务。
- 本地日志只记录内部 UUID、时间、通用状态码和脱敏错误类别。

## 11. 分发方式

应用生成未签名 `.app` 和 `.dmg`，仅供少量用户私下分发。交付包附带中文首次运行说明：

1. 将应用拖入“应用程序”目录。
2. 首次打开被系统阻止后，进入“系统设置 → 隐私与安全性”。
3. 找到对应拦截提示并选择“仍要打开”。
4. 再次确认启动应用。

项目不配置 App Store、Developer ID 公证和自动更新流程。

## 12. 测试策略

### 12.1 单元测试

- 周期订阅和 Token 资源包响应解析。
- `daily*` 到“五小时窗口”的领域映射。
- 5 小时、周和 Token 使用率计算。
- 零额度、超额、负值、字段缺失和未知订阅类型。
- `null`、401、网络错误和无法解析响应。
- 通知阈值跨越、窗口去重和窗口重置。
- 缓存过期计算和刷新间隔切换。

### 12.2 集成测试

- Keychain 新增、读取、更新和删除。
- 多 Key 并发请求中的全部成功、部分成功和全部失败。
- 启动恢复配置与缓存。
- 登录时启动设置切换。
- 模拟系统休眠恢复后的补充刷新。

### 12.3 手工验收

- 菜单栏在深色、浅色和不同壁纸下可读。
- 点击 Key 行能立即切换菜单栏当前 Key。
- 周期切换不影响资源包行。
- 1、5、15、30 分钟刷新配置生效。
- 离线时保留缓存并显示过期状态，恢复网络后自动更新。
- 未签名应用能够按交付说明在另一台 Mac 上完成首次启动。

## 13. 首版验收标准

- 用户能配置至少 10 个 Key，并在重启后恢复名称、排序和当前选中项。
- 所有真实 Key 只存在 Keychain 中。
- 菜单栏能正确显示当前 Key、当前维度的整数百分比。
- 展开面板能在紧凑列表中清晰呈现全部 Key 的关键状态，并以进度条区分风险；Key 较多时可滚动查看。
- 周期订阅和 Token 资源包都能根据实际字段正确展示。
- 单个 Key 请求失败不影响其他 Key 的刷新和显示。
- 网络异常时保留最后成功数据，并准确标记过期状态。
- 通知达到阈值时触发，且同一窗口内不会重复骚扰。
- 登录时启动和独立设置窗口可正常工作。
- 自动化测试覆盖关键映射、计算、错误处理、缓存和通知逻辑。
- 项目能够生成可私下分发的未签名 `.app` 和 `.dmg`。
