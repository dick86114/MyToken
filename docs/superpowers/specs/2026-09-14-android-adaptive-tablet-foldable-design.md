# MyToken Android 平板与阔折叠适配设计

日期：2026-09-14
状态：设计已获用户确认并审阅

## 1. 背景与目标

MyToken Android 当前以手机纵向布局为基准：一级页面固定使用底部导航，首页和凭证页使用单列列表，详情、编辑、设置和迁移页面横向占满窗口。应用运行在平板、横屏手机、分屏窗口或阔折叠展开态时，会出现内容过度拉伸、列表信息密度偏低、底部导航占用垂直空间等问题。

本次适配的目标是：

- 统一依据窗口实际可用宽度，而不是设备型号或屏幕物理尺寸，选择布局。
- 在紧凑屏保持现有手机体验，在大屏提供侧边导航和更合理的横向信息密度。
- 不改变现有供应商、凭证、刷新、排序、通知和迁移行为。
- 窗口横竖屏切换、分屏缩放或折叠形态变化时，保留当前标签、Pager 位置、表单内容、迁移状态和详情返回栈。
- 继续沿用 MyToken 的液态玻璃视觉语言，不引入与现有设计割裂的组件体系。

目标平台仍为 Android 10（API 29）及以上。

## 2. 非目标

- 不实现首页、凭证列表与详情同时显示的主从双栏布局。
- 不根据具体品牌、型号或折叠角度硬编码特殊交互。
- 不增加平板专属功能、账户体系或服务端依赖。
- 不重构现有 ViewModel、Repository、Room、DataStore、WorkManager 和迁移协议。
- 不改变凭证排序、通知阈值、刷新策略和敏感数据存储规则。
- 不用视口宽度缩放字体，不改变现有触控目标和无障碍语义。

## 3. 响应式原则

### 3.1 窗口宽度来源

使用 Compose 官方窗口自适应 API 获取当前窗口尺寸类，包括：

- 官方 `currentWindowAdaptiveInfo()` 或等价的活动窗口宽度监听能力。
- 将官方宽度类映射为 MyToken 的三档布局模式：
  - `Compact`：宽度小于 `600dp`
  - `Medium`：宽度大于等于 `600dp` 且小于 `840dp`
  - `Expanded`：宽度大于等于 `840dp`

判断依据始终是 Activity 当前可用窗口宽度，不是设备物理宽度或屏幕全宽。因此横屏手机、分屏、自由窗口和阔折叠展开态都遵循同一规则。

### 3.2 统一断点

断点集中定义在 `core-ui`，业务模块不得各自复制 `600/840` 等数字，也不得使用 `BoxWithConstraints` 自行实现另一套导航断点。

窗口尺寸变化时，应用直接按新尺寸重新组合布局，不重建 Activity，不重置业务状态。

### 3.3 状态保持

以下状态由现有 ViewModel、remember 状态或根导航状态持有，并必须跨布局模式切换保持：

- 当前一级标签和 `HorizontalPager` 页面。
- 首页供应商筛选。
- 凭证列表顺序、启停状态和待删除确认状态。
- 设置项滚动位置和表单编辑值。
- 详情、编辑、迁移页面的返回栈和页面状态。
- 迁移扫码、连接、预览和完成的当前阶段。

### 3.4 安全区域

- 根布局继续使用 edge-to-edge。
- 底部导航使用底部导航安全 inset。
- 侧边导航使用左侧安全 inset，并避让刘海、圆角和折叠铰链占用区域。
- 内容区域不得绘制到系统栏、刘海或铰链下。
- 导航模式切换后，旧的底部导航 padding 必须移除，左侧导航 padding 必须及时生效，不能保留双重留白。

## 4. 架构设计

### 4.1 `core-ui`

`core-ui` 提供统一的自适应基础能力：

- `MyTokenLayoutMode`：`Compact`、`Medium`、`Expanded` 三档布局模式。
- 官方窗口宽度类到 `MyTokenLayoutMode` 的纯函数映射，便于单元测试。
- 响应式内容宽度组件，提供居中、最大宽度和统一水平 padding。
- 玻璃侧边导航组件，支持紧凑图标模式和带完整标签的宽侧栏模式。
- 共享导航目标模型，避免底栏和侧栏维护两份标签、图标和选中状态。
- 现有 `LiquidGlassBottomBar` 保持为紧凑模式主导航，并继续使用现有玻璃视觉和动效。

侧边导航建议尺寸：

- `Medium`：约 `72dp` 宽的紧凑栏，图标加短标签。
- `Expanded`：约 `160dp` 到 `184dp` 宽的展开栏，图标加完整标签。
- 侧栏使用玻璃容器、圆角、选中强调色和无障碍语义，与底栏一致。

### 4.2 `app`

`app` 负责组合根导航壳：

- `MyTokenApp` 获取当前 `MyTokenLayoutMode`。
- 一级页面在 `Compact` 显示现有底部导航。
- 一级页面在 `Medium` 和 `Expanded` 显示左侧导航栏。
- 详情、编辑、迁移等非一级页面在各尺寸下继续隐藏主导航，保持现有返回语义。
- 根 `Scaffold` 根据导航模式计算内容 padding，并继续承接 `HorizontalPager`。
- 点击导航项仍通过现有 `selectTab` 和 `pagerState` 切换页面。
- 切换布局模式不能清空 `backStack` 或改变当前 `AppScreen`。

根导航只调整布局，不改变 `AppScreen` 的定义，也不引入新的路由框架。

### 4.3 Feature 模块

Feature 模块只接收布局模式或内容宽度约束，不读取 Activity，不自行判断设备形态：

- `feature-home`：调整凭证网格和卡片内部指标列数。
- `feature-credentials`：调整列表/网格和可拖拽排序容器。
- `feature-settings`：调整分区网格和长内容横跨列。
- `feature-transfer`：调整扫码框、导入预览和完成页宽度。
- 详情与编辑页面位于现有 `feature-home` 和 `feature-credentials` 中，增加居中限宽。

## 5. 页面设计

### 5.1 首页

- `Compact`：单列凭证卡片。
- `Medium`：双列凭证网格；单张卡片可用宽度低于 `260dp` 时回退为单列，避免卡片内容被压缩。
- `Expanded`：三列凭证网格，同样保证单张卡片可用宽度不低于 `260dp`。
- 供应商筛选 chips 在紧凑屏保持横向滚动；在宽屏改为自动换行，避免隐藏可选供应商。
- 下拉刷新作用于整个网格，刷新状态和单凭证错误状态保持现有语义。
- 卡片内部指标网格在窄卡片中允许降为单列，在宽卡片中维持双列。
- 凭证名称、套餐名和指标值继续使用省略、换行或受控高度策略，不能互相覆盖。

### 5.2 凭证页

- `Compact`：保持现有单列 `LazyColumn`。
- `Medium`：单列居中列表，限制最大宽度，避免中等窗口中的行内容过度拉伸。
- `Expanded`：双列 `LazyVerticalGrid`，使用 reorderable 库的 Lazy Grid 支持实现拖拽排序。
- 列表顺序仍是唯一的全局顺序；从任一网格位置拖到另一位置时，按线性索引更新排序。
- 启停、编辑、删除、删除确认和空状态行为不变。
- 空状态内容限制最大宽度并居中。

### 5.3 设置页

- `Compact`：保持现有单列分区。
- `Medium` 和 `Expanded`：使用双列分区网格。
- “主题”“刷新”“通知”“数据迁移”等独立分区可以并排。
- “关于”包含更新日志和更新操作，横向跨两列，避免内部内容被压缩。
- 分区顺序在从单列切换到双列时保持稳定。
- 现有 `settings_list` 测试语义需要保留，或提供等价的稳定测试标识。

### 5.4 详情页

- 内容居中，最大阅读宽度约为 `840dp`。
- 顶级标题、状态、套餐指标、模型和配置分区保持现有纵向顺序。
- 底部刷新、签到、编辑、删除操作条同样居中并限制最大宽度。
- 窄窗口继续允许操作条单行排列；如果实际内容无法容纳，应通过稳定高度或受控换行处理，不能覆盖页面内容。
- 返回、刷新、编辑、删除和签到回调不变。

### 5.5 凭证编辑页

- 表单居中，最大宽度约为 `720dp`。
- 新增凭证和编辑凭证使用相同约束。
- 动态字段、密钥显示切换、连接测试、校验错误和保存行为不变。
- 键盘出现时保持可滚动，不因大屏限宽导致底部按钮不可达。

### 5.6 迁移页面

- 扫码页：标题和取消操作居中，相机取景区域使用稳定宽高比并限制最大宽度，避免在平板上被拉伸成过高画面。
- 导入预览：宽屏可以将迁移摘要与凭证列表并排；紧凑屏保持现有上下结构。
- 确认、跳过、取消和覆盖导入按钮保持现有语义，并在限宽内容区内排列。
- 完成页和失败页内容居中并限制最大宽度。
- CameraX、ML Kit、局域网传输和解密流程不变。

## 6. 内容宽度与列数

- 首页网格最大内容宽度约为 `1440dp`，并水平居中。
- 凭证列表最大内容宽度约为 `960dp`；展开态双列网格可使用相同上限。
- 设置网格最大内容宽度约为 `1200dp`。
- 详情最大阅读宽度约为 `840dp`。
- 编辑表单最大阅读宽度约为 `720dp`。
- 空状态、错误状态和完成状态最大宽度约为 `480dp`。
- 列数只由布局模式和实际可用内容宽度决定，不随字体大小改变。
- 保留手机端现有 `12dp` 到 `16dp` 的内容边距；大屏使用 `20dp` 到 `24dp`，但不得让内容贴边。
- 侧栏宽度必须从内容可用宽度中扣除，网格不能只按窗口全宽计算。

## 7. 交互与无障碍

- 底栏、侧栏和页面内操作保持原有 `contentDescription` 或等价语义。
- 大屏布局不改变点击、长按、拖拽和滑动方向。
- 凭证拖拽排序在列表和网格中都必须有触觉反馈。
- 焦点顺序按视觉顺序排列：侧栏、顶部栏、页面内容、底部操作。
- 大字体下允许文字换行或增加容器高度，但不能与图标、开关和相邻操作重叠。
- 深色和浅色主题都使用现有语义色，不新增仅靠颜色区分的状态。
- 横屏时保持可滚动，不能因固定高度导致底部操作不可达。

## 8. 错误与边界情况

- 分屏或自由窗口宽度在断点附近反复变化时，导航模式可以切换，但状态不能丢失。
- 折叠展开和折叠过程中，内容按当前窗口宽度响应；铰链区域通过 inset 避让。
- 空列表、加载中、失败、禁用和过期数据状态在三种布局模式下都可见且可操作。
- 单个凭证刷新失败不能影响网格其他卡片。
- 相机权限被拒绝、迁移连接失败或导入失败时，大屏布局仍需显示完整错误和返回入口。
- 长凭证名、长套餐名、较长阈值说明和更新日志不得撑破卡片或覆盖相邻组件。
- 侧栏和底栏不能同时出现。
- 非一级页面切换宽度时不能意外显示一级导航。

## 9. 测试策略

### 9.1 单元测试

- 验证宽度映射边界：
  - `599dp` 映射为 `Compact`
  - `600dp` 映射为 `Medium`
  - `839dp` 映射为 `Medium`
  - `840dp` 映射为 `Expanded`
- 验证首页、凭证和设置列数计算。
- 验证内容宽度扣除侧栏后仍得到正确列数。
- 验证导航目标映射和选中状态。

### 9.2 Compose UI 测试

使用 Robolectric 或 Compose 测试现有结构，至少覆盖：

- `w400dp`：底部导航、首页单列、凭证单列、设置单列。
- `w700dp`：侧边紧凑栏、首页双列、凭证居中单列、设置双列。
- `w1000dp`：侧边展开栏、首页三列、凭证双列、设置双列。
- 断点附近的布局切换。
- 首页供应商筛选、下拉刷新和错误卡片在大屏下仍可操作。
- 凭证网格拖拽排序仍更新同一线性顺序。
- 设置页“关于”横跨两列，且保持 `settings_list` 或等价测试标识。
- 详情、编辑、扫码和导入预览在大屏下正确限宽。
- 长文本、大字体、深色主题下关键操作可见且不重叠。

### 9.3 回归测试

- 保留所有现有手机尺寸 Compose 测试。
- 保留 ViewModel、Repository、Room、DataStore、WorkManager、迁移和供应商测试。
- 验证从 `Compact` 切换到 `Medium` 再回到 `Compact` 后 Pager 页码和返回栈不变。
- 验证布局变化不会重复触发刷新或重新创建业务 ViewModel。
- 执行 `./gradlew test`。
- 执行 `./gradlew :app:assembleDebug`。
- 执行 `./gradlew :app:assembleDebugAndroidTest`，确保测试 APK 可编译。
- 在可用的大屏模拟器或真机上执行截图验收，覆盖手机、平板横竖屏和阔折叠展开态。

## 10. 验收标准

- Android 10 及以上设备在手机上保持现有底部导航和单列体验。
- 横屏手机、分屏窗口、平板和阔折叠展开态统一按可用宽度切换布局。
- `Medium` 和 `Expanded` 的一级页面使用左侧导航，不显示底部导航。
- 首页、凭证和设置页面按设计增加列数或限制内容宽度。
- 详情、编辑、扫码、导入预览和空状态在大屏下居中且内容不过度拉伸。
- 宽度变化后当前标签、Pager、表单、迁移状态和详情返回栈保持不变。
- 凭证拖拽排序在列表和网格中均保持正确。
- 长文本、大字体、深色主题和断点附近缩放不出现重叠或不可达操作。
- 现有手机端行为、数据协议和安全策略不回归。
- 全模块 JVM 测试、Debug APK 和 AndroidTest APK 构建通过。

## 11. 交付边界

本次交付只包含 Android 客户端布局与导航适配，不包含：

- macOS 客户端改动。
- 主从双栏详情布局。
- 新的平板专属业务能力。
- 应用发布、商店截图或文案更新。

完成后应补充 Android 手工验收清单中的平板、横屏和阔折叠检查项。
