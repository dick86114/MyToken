# Codex 当前分组检测设计规格

## 1. 背景与目标

MyRoutin 已能通过 `GET https://api.routin.ai/plan/v1/usage` 获取每个 plan Key 的分组名称和倍率，但该接口只返回可用分组列表，不能说明一次 Codex 请求最终路由到了哪个分组。

本功能允许用户在菜单栏弹窗中对单个 Key 手动执行一次低成本 Codex 探测请求，再从已登录 Routin 账号的模型请求日志中读取该请求实际使用的分组。识别成功后，应用在该 Key 的分组倍率文本中将对应的完整“分组名 × 倍率”显示为绿色。

本功能只回答“这个 Key 的本次 Codex 探测请求使用了哪个分组”，不推断其他模型的路由分组，也不承诺后续请求永久使用同一分组。

## 2. 已确认范围

### 2.1 包含

- 每个 Key 独立提供“获取 Codex 当前分组”手动入口。
- 探测会发送一次真实 Codex 请求，并产生极少量额度消耗。
- 未登录 Routin 时打开应用现有的受控网页登录窗口，登录完成后自动继续。
- 使用当前登录账号的模型请求日志确认探测记录和分组名称。
- 严格校验登录账号与 Key 的关联，不能将一个账号的日志结果用于另一个账号的 Key。
- 成功结果按 Key 持久化，并显示检测时间。
- 倍率继续取自用量 API 的最新结果，不缓存检测时的倍率。
- 当前倍率列表包含检测到的分组时，将完整的“分组名 × 倍率”显示为绿色。

### 2.2 不包含

- 自动随用量刷新或弹窗打开执行探测。
- 批量检测全部 Key。
- 读取、导出或保存 Routin Cookie、访问令牌、密码或验证码。
- 通过未公开的 Routin 日志 API 获取数据。
- 把最近一条普通日志猜测为当前 Key 的请求。
- 判断非 Codex 模型使用的分组。
- 将检测结果理解为永久路由承诺。

## 3. 方案选择

采用“真实探测请求 + 内嵌网页登录 + 页面语义读取”方案。

应用使用目标 plan Key 向 Routin 的 Responses 端点发送一次最小 Codex 请求，并通过该请求独有的 `User-Agent` 探测标识在当前登录账号的模型请求日志中寻找唯一记录。日志匹配成功后读取分组名称。

不调用网页内部的非公开接口。这样不会把网页登录凭证带出 `WKWebView`，也降低未公开接口变更造成的安全和维护风险。

不采用“探测后直接读取最新一条日志”的方式，因为用户可能同时通过其他客户端发起请求，时间相近不能证明日志属于目标 Key。

## 4. 架构

### 4.1 `CodexGroupDetectionService`

新增主状态服务，职责包括：

- 接收目标 `KeyConfiguration.id`。
- 串行化探测任务，同一时间全应用最多运行一个任务。
- 协调网页登录、账号校验、探测请求和日志轮询。
- 维护按 Key 隔离的运行状态。
- 在 Key 删除、Key 密文修改或应用终止时取消相关任务。

该服务不直接解析 SwiftUI，也不直接管理 Key 明文持久化。执行探测时临时从现有 `KeyRepository` 读取目标 Key，完成或取消后不保留明文副本。

### 4.2 `CodexGroupProbeClient`

新增可替换的网络客户端，职责仅限发送最小 Codex 探测请求。

请求规则：

- 使用目标 plan Key 设置 `Authorization: Bearer <plan-key>`。
- 使用 Routin plan Responses 端点。
- 每次生成一次性 UUID，并设置唯一 `User-Agent`，格式为 `MyRoutin-Group-Probe/<UUID>`。
- 请求正文使用无敏感信息的固定短文本。
- 限制最小输出长度，不启用工具、文件、图片或长推理。
- 设置明确的短超时。
- 不把 UUID、完整 Key、请求正文或响应正文写入持久化日志。

模型通过独立的 `CodexProbeModelPolicy` 选择。策略维护少量、按成本从低到高排列且已确认可走 Codex 分组的模型候选；一次检测默认只发送一个成功请求。仅当服务端在创建请求前明确返回“模型不存在或不可用”时才尝试下一候选；对于超时、未知服务器错误或可能已经创建日志的失败，不自动换模型，避免重复计费。

候选列表集中在单一策略中并有单元测试，模型下线时可以局部更新，不把模型名散落在视图或状态机中。

### 4.3 `RoutinAccountIdentityReader`

复用现有 `RoutinWebSession` 和 `WKWebsiteDataStore.default()` 登录会话，通过账户页可见内容读取：

- 只读邮箱，用于生成稳定账号指纹。
- 用户名，用于界面提示。

邮箱先去除首尾空白并转为小写，再计算 SHA-256。应用只返回和保存摘要，不保存邮箱原文。用户名可以保存，但不能用于安全判断，因为用户名可能修改或重名。

若账户页无法取得只读邮箱，则本次检测失败为“无法确认 Routin 账号”，不能降级使用用户名建立绑定。

### 4.4 `RoutinModelRequestLogReader`

复用同一个 `WKWebView` 会话访问：

`https://routin.ai/dashboard/logs/model-requests`

读取规则：

- 确认页面不是登录页。
- 等待日志列表完成加载。
- 每轮触发页面自身的“刷新”操作或重新读取已更新列表。
- 只查找 `User-Agent` 精确等于本次探测标识的记录。
- 同时要求日志时间不早于探测开始时间的容差下界。
- 匹配结果必须恰好一条；零条继续轮询，多条视为无法唯一确认。
- 从匹配行的令牌/分组单元格读取完整分组名称。
- 最长轮询约 30 秒，轮询间隔采用固定短间隔并允许取消。

解析器基于页面的表格、列标题和可见文本语义，不依赖脆弱的全局元素序号。页面缺少日志表、`User-Agent` 列语义、分组内容或刷新能力时，返回“页面结构发生变化”，不能报告账号不匹配。

## 5. 数据模型与持久化

新增记录：

```swift
struct CodexGroupDetectionRecord: Codable, Equatable, Sendable {
    let keyID: UUID
    let accountFingerprint: String
    let accountDisplayName: String
    let groupName: String
    let detectedAt: Date
}
```

使用独立仓库按 `keyID` 保存到 `UserDefaults`，不修改现有 Key 密钥存储方式。

字段规则：

- `accountFingerprint`：规范化邮箱的 SHA-256 摘要。
- `accountDisplayName`：检测时用户名，仅用于展示。
- `groupName`：日志返回的完整分组名称。
- `detectedAt`：成功读取日志的本地绝对时间。
- 不保存探测 UUID、完整 Key、邮箱、Cookie、网页令牌、请求体或响应体。

生命周期规则：

- Key 密文修改：立即删除该 Key 的检测记录和账号关联。
- Key 删除：同步删除该 Key 的检测记录。
- Key 别名修改或排序变化：保留记录。
- Routin 网页退出登录：清除网页会话，但保留历史记录；下次检测必须重新校验登录账号指纹。
- 用户主动解除账号关联：删除该 Key 的记录和绿色高亮。
- 新检测得到其他分组：以新结果替换旧记录。
- 当前倍率列表找不到历史分组：保留记录供诊断，但不显示绿色。

旧版本没有该存储项时按空记录处理，不需要数据迁移。

## 6. 状态机与账号关联

每个 Key 的运行状态独立维护：

- `idle`
- `needsLogin`
- `probing`
- `waitingForLog`
- `succeeded`
- `accountMismatch`
- `failed`

应用全局最多存在一个活跃探测任务，其他 Key 的探测按钮在任务结束前禁用。

### 6.1 尚未绑定的 Key

1. 取得当前登录账号指纹，但暂不保存绑定。
2. 使用目标 Key 发起探测。
3. 在当前账号日志中找到唯一探测记录。
4. 只有第 3 步成功后，才同时保存账号指纹和分组结果。

找不到日志不能等同于账号不匹配。首次绑定时，即使满足以下条件，也只能显示“未在当前账号日志中找到探测记录，请检查账号或稍后重试”：

- 探测请求已收到明确成功响应；
- 日志页面已正常加载且解析结构完整；
- 页面刷新正常执行；
- 整个轮询窗口内没有本次唯一 `User-Agent` 记录；
- 没有网络错误、登录失效或页面结构错误。

应用无法仅凭“没有日志”排除日志延迟，因此不建立绑定，也不清除其他 Key 的记录。提示同时提供“刷新日志后重试”和“切换账号”操作。确定性的“当前账号与此 Key 不匹配”只用于已有绑定指纹与当前登录指纹不同的情形。

### 6.2 已绑定的 Key

发送付费探测请求前读取当前登录账号指纹：

- 指纹相同：继续探测。
- 指纹不同：立即阻止，不发送请求，状态为 `accountMismatch`。
- 无法取得指纹：不发送请求，提示无法确认账号。

因此，已绑定 Key 不会在错误账号下产生探测费用。

## 7. 用户流程

1. 用户在某个 Key 行点击定位图标按钮“获取 Codex 当前分组”。
2. 首次操作显示费用确认，说明将发送一次真实 Codex 请求并产生极少量额度消耗。
3. 用户确认选择可记忆；设置页提供恢复“每次询问”的选项。
4. 应用检查网页登录状态。
5. 未登录时打开现有 Routin 登录窗口，用户自行完成密码、验证码或第三方授权。
6. 登录成功后自动恢复原 Key 的待处理探测。
7. 应用读取账号指纹并执行绑定前校验。
8. 发送最小 Codex 请求，随后轮询请求日志。
9. 找到唯一记录并取得分组名称。
10. 校验该名称是否存在于此 Key 最新用量快照的 `groupMultipliers`。
11. 校验成功后保存记录并更新界面；若倍率数据缺失或分组不存在，则保存日志识别结果但不点亮，并提示用户刷新用量。

登录窗口继续使用官方页面。应用不代填、不截获也不保存账号密码、验证码或第三方授权信息。

## 8. 菜单栏界面

### 8.1 Key 行操作

每个 Key 行在分组倍率区域附近增加定位图标按钮，使用系统图标和悬停提示“获取 Codex 当前分组”。

- 空闲时显示定位图标。
- 当前 Key 正在探测时替换为固定尺寸 `ProgressView`。
- 其他 Key 有任务运行时按钮禁用。
- 固定按钮和进度指示尺寸，不能改变行高或挤压倍率文本。

### 8.2 分组倍率着色

现有合并字符串改为逐项渲染，但保持单行、右对齐和原有分隔形式：

- 未识别：`Codex ×1、Codex Pro ×2` 全部使用现有次要文字色。
- 识别为 `Codex`：完整的 `Codex ×1` 使用系统绿色，其他项保持原色。
- 使用分组名称完全相等匹配，不采用包含、前缀或忽略空格的模糊匹配。
- 倍率来自当前 `UsageSnapshot.groupMultipliers`，因此 API 倍率变化后绿色项自动显示新倍率。

检测成功后显示紧凑辅助文字，例如：

`Codex 当前分组，检测于 14:30`

辅助功能朗读必须包含 Key 名称、当前分组、倍率和检测时间，不能只通过颜色表达状态。

### 8.3 账号操作

已有关联记录时可在设置页查看“已关联账号 <用户名>”并执行“解除关联”。用户名仅用于提示。

账号不匹配时提供“切换账号”操作：

- 清除当前 Routin 网页会话。
- 打开官方登录页。
- 不自动删除目标 Key 的历史绑定。
- 新账号登录后重新校验指纹，匹配才允许继续。

## 9. 错误与降级

错误提示必须区分：

- `请先登录 Routin`
- `当前登录账号与此 Key 不匹配`
- `无法确认 Routin 账号`
- `Key 无效或订阅不可用`
- `Codex 探测模型暂不可用`
- `探测请求失败`
- `日志生成超时，可稍后重试`
- `未在当前账号日志中找到探测记录，请检查账号或稍后重试`
- `Routin 日志页面结构发生变化`
- `检测到的分组不在当前倍率列表中，请先刷新用量`
- `探测已取消`

失败规则：

- 网络失败不清除已有成功记录，但本次不更新时间。
- 已绑定账号指纹不匹配时隐藏该 Key 的绿色展示状态；持久化历史记录保留至用户解除关联、修改 Key 或成功切回原账号，以便阻止错误账号继续探测。
- Key 密文被修改或 Key 被删除时，取消任务并删除记录。
- 页面结构变化、登录失效、超时或解析失败不能误报为账号不匹配。
- 探测响应成功但日志读取失败时，不自动重复发送探测请求。
- 应用重新启动后不恢复未完成的探测任务，只显示最后一次成功结果。

## 10. 安全与隐私

- Key 明文继续由现有本地 Key 存储管理，只在请求期间临时读取。
- 网页认证状态仅存在于 `WKWebsiteDataStore.default()`。
- 不读取或导出 Cookie，不向 `URLSession` 注入网页登录凭证。
- 不持久化邮箱原文，只保存规范化邮箱的 SHA-256 摘要。
- 诊断日志不得包含完整 Key、邮箱、Cookie、授权头、探测 UUID、请求体或响应体。
- 网页导航继续沿用现有 Routin 域名和已批准身份提供商白名单。
- 仅允许用户主动触发付费探测，不允许后台定时执行。

## 11. 测试与验证

### 11.1 单元测试

- 探测请求使用正确端点、Bearer 授权、唯一 `User-Agent`、最小请求体和短超时。
- 模型策略按成本排序，只在明确的模型不可用错误时回退。
- 未知错误、超时和可能已创建请求的失败不会自动发送第二次探测。
- 邮箱规范化和 SHA-256 指纹稳定，不保存邮箱原文。
- 日志解析器按唯一 `User-Agent` 和时间下界匹配，忽略旧日志和同时发生的普通请求。
- 零条、多条、页面缺列、登录页和结构变化分别返回正确错误。
- 已绑定账号指纹不同时在发请求前终止。
- 检测记录按 Key 隔离，Key 修改和删除正确清理。
- 旧缓存缺少检测记录时正常启动。

### 11.2 视图与集成测试

- 分组倍率逐项渲染，只有完全匹配项使用绿色。
- 倍率变化时绿色项显示最新倍率。
- 分组不存在于当前快照时不点亮。
- 探测按钮和进度状态尺寸稳定，不改变 Key 行布局。
- 状态变化、登录恢复、取消和解除关联正确反映到菜单栏弹窗及设置页。
- 无障碍标签不依赖颜色，并包含分组、倍率和检测时间。

### 11.3 人工验证

使用获得授权的测试账号和 plan Key：

1. 未登录时触发探测，确认打开官方登录页并在登录后恢复。
2. 确认只产生一次低成本 Codex 请求。
3. 在官方日志页确认唯一 `User-Agent`、实际分组和应用结果一致。
4. 确认对应“分组名 × 最新倍率”完整变绿。
5. 切换到不匹配账号，确认请求发送前被阻止。
6. 制造并发普通请求，确认不会误识别。
7. 修改 Key 后确认绑定和高亮被清除。

人工验证记录只写日期、可见结果、请求次数和是否产生少量费用，不记录账号、邮箱、Key、Cookie、探测标识或请求内容。

## 12. 验收标准

- 用户能在任意单个 Key 行手动获取 Codex 当前分组。
- 未登录时必须要求用户在官方页面完成登录，并在成功后恢复操作。
- 一个成功检测最多产生一次正常探测请求；只有明确模型不可用时允许候选回退。
- 日志必须通过本次唯一探测标识匹配，不能仅依赖最新时间。
- 已绑定 Key 在错误登录账号下不会发送付费请求。
- 成功识别后，对应的完整“分组名 × API 最新倍率”显示为绿色。
- 结果按 Key 持久化，重启后仍可展示。
- Key 密文修改、Key 删除或用户解除关联后不再展示旧结果。
- 页面变化、网络失败、日志延迟和首次绑定未找到日志不会被误报为账号不匹配。
- 应用不保存邮箱原文、Cookie、网页登录令牌、探测 UUID 或完整 Key。
