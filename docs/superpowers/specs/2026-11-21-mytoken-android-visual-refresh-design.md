# MyToken Android 视觉重构设计文档

- 状态：**已确认（Approved v1，2026-11-21）**
- 日期：2026-11-21
- 范围：Android 客户端首页、卡片系统、凭证列表、新增/编辑凭证、设置、卡片详情
- 不在范围：数据层、供应商协议、迁移协议、macOS 端、小组件布局逻辑
- 设计稿：`docs/design/home-hifi.html`、`cards-spec.html`、`pages.html`（自包含高保真 HTML）

---

## 1. 背景

Android 客户端目前的功能完整，但视觉上面临三个具体问题：

1. **颜色“脏”**：语义色是灰调的（warning `#BF8126`、critical `#D25A60`、positive `#2E9B77`），
   只有品牌蓝是高彩度；同一颜色又同时承担状态、分类、交互三种意义。
2. **表面层级过多**：浅色模式下同一屏叠了 6–8 层近白表面（canvas、surface、surfaceVariant、
   62% 卡片、78% 圆钮、72% chip、4.5% pill），层与层只差 1–2%，叠成雾。
   深色模式则是蓝黑表面加 4–8% 白色叠加。
3. **没有“一个主张”**：玻璃、流星、星星、健康短条、彩色 pill、页脚 CTA 各自成立，
   但没有一个反复出现的母题；眼睛找不到先看哪里。

首页卡片在内容上也有结构性差异：单套餐总量、5h+周、5h+周+月、余额+赠送、
重置卡、简洁/完整两种密度，目前靠不同 provider 的定制布局拼接，缺少统一骨架。

本次重构以 **“安静的仪表”** 为主张：默认状态几乎不说话，需要用户处理时只在一个地方、
用一种颜色说清楚。通过一套 token、一个卡片骨架和一个签名元素（270° 弧线 + 数字排版）
把五个页面收进同一个系统。

## 2. 目标与非目标

### 2.1 目标

- 建立单一来源的视觉 token：颜色、表面、字号、间距、圆角、动效。
- 用一种卡片骨架覆盖 8 类供应商内容，简洁/完整只改变密度，不维护两套界面。
- 首页首屏更早出现数据：头部从 4 条横带压到 3 行（更新提示 / 状态+筛选 / 健康标尺），
  第一张卡比现在提前约 80dp。
- 颜色只用于数据可视化和异常：正常状态中性，分类用墨色深浅，蓝只做交互。
- 去掉卡片内部分割线，用 14dp 行距、左右分栏间距和小标题分组。
- 四个二级页面（列表、新增、设置、详情）按“身份 → 当前状态 → 操作”重新组织。
- 明暗两种主题、动态字体、减少动态、48dp 触控区全部纳入验收。

### 2.2 非目标

- 不改 `UsageProvider`、`UsageSnapshot`、`UsageMetric` 的语义或 provider 接口。
- 不改 Android 与 macOS 的共享契约、迁移 schema、widget contract。
- 不引入新的后端、账号体系或云端同步。
- 不新增凭证类型、供应商或指标字段；只重新呈现现有数据。
- 不做历史趋势、折线图或用量预测；当前数据层没有历史。
- 不追求像素级复刻 iOS 或 Material；本次只统一 MyToken 自己的语言。

### 2.3 反目标（即使技术上可行也不做）

- 不再用半透明卡片叠加模拟“玻璃”。Android 上没有真实 blur 时，假玻璃就是脏的主要来源。
- 不用彩色状态 pill 同时表达正常状态；正常状态不持续发绿。
- 不把简洁模式做成“完整模式的截断版”；两种模式都必须是完整、可读的界面。
- 不把设置页做成所有功能的收件箱；分组按用户意图，不按代码模块。
- 不为视觉重构改动安全路径（`LocalKeyStore` / Keystore / secret 读取）或日志脱敏。

## 3. 约束

- **双端语义一致**：provider 能力、指标语义、凭证元数据与迁移格式不变；
  Android 只改呈现。共享 fixture 与测试不能因为视觉重构而失效。
- **现有测试文化**：Android 有大量 Robolectric/Compose 测试和 testTag 断言；
  重构要保持 tag 语义（或同一 PR 内更新断言）。macOS 的源码文本断言不受影响。
- **性能**：沿用现有的滚动优化（关闭 overscroll、Canvas 自绘进度条、避免卡片常驻
  graphicsLayer）。不引入实时 blur、无限描边、每帧重绘。
- **安全**：密钥永不出现在日志、卡片、详情页或分享卡片；诊断仍走脱敏路径。
- **小屏与 OEM**：390dp 手机为第一目标；OriginOS/vivo 的 overscroll、后台限制不回退。
  minSdk 29，Compose Material 3 现有版本。
- **本地化**：用户文案保持中文；数字/单位使用 tabular numerals；不新增英文长句。
- **迁移策略**：分阶段落地，每个阶段可独立运行 `./gradlew test` 并在真机验收。

## 4. 设计主张

> **安静的仪表**：默认状态几乎不说话，需要你管的时候只在一个地方、用一种颜色说清楚。

由此推导出五条不可协商的规则：

1. **一屏最多 3 个色相**：中性 + 品牌蓝 + 一个异常色（warning/critical 同属暖色信号，
   按状态只会出现一个）。正常状态不出现绿色文字或徽章。
2. **颜色只出现在数据可视化里**：弧线、进度条、构成条、异常文字。状态 chrome
   （pill、按钮底、分割线、圆点）不再复制同一信息。
3. **一个卡片骨架**：身份 → 主指标 → 次级窗口 → facts → 页脚。不同供应商只决定哪些槽位有内容。
4. **分类色用墨色深浅**：充值/赠金、输入/输出/缓存、月度/购买/赠送都用 ink 的三档，
   不借状态色或交互色。
5. **签名只留一个**：270° 弧线 + tabular 数字排版 + 唯一那句彩色提示。
   其他装饰（发光、渐变、玻璃）全部删除或降为一次性状态。

## 5. 方案与取舍

### 5.1 视觉方向

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| **A（采用）** | 一套卡片骨架，简洁/完整只改密度；共用 token | 维护成本低、两模式一致；需要重新设计卡片骨架 |
| B | 简洁模式做仪表盘、完整模式做报表，两套布局 | 两套组件、两套测试，长期分叉；用户切换时视觉断裂 |
| C | 只保留一种自适应布局，砍掉模式切换 | 违背“两种模式都有真实用户”的约束；不可接受 |

**决定：A。** 两种模式都保留，切换器留在头部，一次点击可达。

### 5.2 材质

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| **A（采用）** | 实色表面 + 1px hairline；弹层用 scrim + 阴影 | 干净、稳定、无 GPU 成本；需要靠间距/对比建立层级 |
| B | 真实 blur 玻璃（Android 12+ RenderEffect） | 滚动成本高，OriginOS 掉帧风险；低版本降级不一致 |
| C | 继续用半透明色模拟玻璃 | 当前“脏”的主要来源；放弃 |

**决定：A。** `LiquidGlassSurface` 保留 API 名称（历史原因），实现改为实色表面；
浮层（sheet、popover、dialog）才允许阴影。

### 5.3 模式切换位置

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| **A（采用）** | 头部中央，纯文字「简洁 / 完整」+ 2dp 下划线 | 一次点击、可发现、视觉重量几乎为零 |
| B | 保持 156×34 填充轨道 | 比首屏任何数据都重；像工具栏里的开关 |
| C | 收进设置 | 头部最干净，但切换变三次点击，惩罚临时切完整模式的人 |
| D | 单个图标按钮 | 两态图标有“当前状态还是目标状态”的歧义 |

**决定：A。** 切换写入现有偏好；默认沿用当前实现，不引入自适应默认。

### 5.4 信号色

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| **A（采用）** | 每个状态拆成 fill / text 两档；正常中性；颜色只做数据/异常 | 弧线亮、文字可读；需要维护 6 个色值 |
| B | 保持现有灰调单色三件套 | 弧线不亮、文字不清；正是当前“脏”的原因 |
| C | 全部用系统鲜亮色，不做 text 变体 | 鲜亮色做小字对比度不足 |

**决定：A。** 详见 §6.1。

### 5.5 页面结构

| 页面 | 考虑过的方案 | 采用 |
| --- | --- | --- |
| 凭证列表 | 分组列表 vs 独立卡片 | 独立卡片，和首页同一张卡语言；无内部分割线 |
| 新增凭证 | 8 个 chip 平铺 vs 当前供应商一行 + 选择 sheet | 行 + sheet，减少首屏长度，字段随供应商变化 |
| 设置 | 可展开卡片堆叠 vs 五个意图分组 | 五个分组：外观 / 刷新 / 通知 / 数据 / 关于；无内部分割线 |
| 卡片详情 | 重复首页卡片 + 多张状态卡 vs Hero + 全部窗口 + 事实 + 模型 + 配置 | Hero + 分节阅读；数据时间合并进 Hero 页脚 |

## 6. 设计系统

### 6.1 颜色 token

#### 角色

| Token | 用途 | 规则 |
| --- | --- | --- |
| `canvas` | 页面底色 | 不使用渐变 |
| `surface` | 卡片、sheet、行 | 实色，不叠 alpha |
| `subtle` | 输入框、内嵌槽、chip | 只叠在 surface 上 |
| `line` | 卡片/弹层边界、输入框描边 | 1px；卡片内部不再画线 |
| `ink` | 主文字、数字 | — |
| `muted` | 标签、辅助说明 | AA ≥ 4.5:1 |
| `actionFill` / `actionText` | 按钮、链接、选中、焦点 | 只做交互，不做数据 |
| `positiveFill` / `positiveText` | 正常用量、健康 | 只出现在弧线/细条/状态点 |
| `warningFill` / `warningText` | 接近上限 | 只出现在弧线/细条/异常句 |
| `criticalFill` / `criticalText` | 超限、失败 | 只出现在弧线/细条/异常句 |
| `cat1/2/3` | 余额构成、Token 构成 | 墨色深浅，不借状态色 |

### 6.2 表面与层级

| 层级 | 做法 |
| --- | --- |
| 页面 | `canvas` 实色 |
| 卡片 | `surface` + 1px `line` + 20dp 圆角；无阴影 |
| 内嵌槽 / 输入框 | `subtle` + 1px `line` + 12dp 圆角 |
| 卡片内部 | **不再画分割线**；用 14dp 行距、40/60 分栏 18dp 间距、小标题分组 |
| 浮层（sheet / menu / dialog） | `surface` + 阴影 + scrim；sheet 顶部 24dp 圆角 |
| 滚动边缘 | 固定头部下方，仅在内容滚入时出现 1px line + 12dp 渐隐，不常驻 |

禁止：卡片使用 `copy(alpha=0.62/0.72/0.78)`、半透明表面叠半透明表面、
卡片常驻阴影、卡片内渐变描边。

### 6.3 字体

| Token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `display` | 32 / 36 | 750 | 余额金额、详情 Hero 数字（仅数字） |
| `title` | 22 / 28 | 700 | 页面标题（凭证、设置） |
| `section` | 16 / 22 | 650 | 区块标题、卡片名（完整） |
| `body` | 14 / 21 | 400 | 正文、设置行 |
| `label` | 12.5 / 18 | 500 | 指标标签、按钮 |
| `caption` | 11.5 / 16 | 400 | 说明、图例、页脚 |
| `micro` | 11 / 15 | 600 | 拉丁单位、重置卡数字；**不用于中文句子** |

规则：

- 中文行高 1.45，字距 0；负字距只用于数字（大数字 -0.8px）。
- 数字统一 `fontFeatureSettings = "tnum"`（tabular numerals）。
- 货币符号 0.6em，与数字基线对齐；单位用 `micro`。
- 最小中文 11.5sp；不再出现 9 / 9.5 / 10 / 10.5sp 的中文。
- 所有文本走 `MyTokenType`，业务文件禁止内联 `fontSize` / `letterSpacing`。

| 项 | 值 |
| --- | --- |
| 间距 scale | 2 / 4 / 8 / 12 / 16 / 24 / 32 |
| 页面边距 | 16dp |
| 卡片内边距 | 简洁 14dp / 完整 16dp / 详情 16dp |
| 网格间距 | 简洁 8dp / 完整 12dp |
| 区块间距 | 24dp；设置 section 之间 20dp |
| 卡片圆角 | 20dp |
| 内嵌/按钮圆角 | 12dp |
| 行圆角（列表） | 18dp |
| 弧线 | 270°，3.5dp，圆头；简洁 52dp，完整 64dp，详情 88dp |
| 健康标尺 | 4dp 高，4dp 间距 |
| 开关 | 46×28dp |
| 触控区 | 48dp（图标、开关、重置卡 chip、菜单） |

| 导航栏 | 44dp；返回/分享/更多 44×44dp |

### 6.5 图形语言

- **弧线**：270°，从 135° 起顺时针；轨道 `track`，进度用状态 fill；
  百分比在圆心，tabular；无渐变、无发光。
- **进度条**：3–5dp 高，圆角；轨道 `track`；填充用状态 fill。
- **构成条**：5dp 高；三段用 `cat1/2/3`；图例用 5dp 圆点 + 11.5sp 文本。
- **图标**：1.6–1.8dp stroke，圆头；尺寸 15–20dp；颜色 ink 或 muted；
  不用彩色图标（供应商 Logo 除外）。
- **Logo plate**：白底 + 1px line + 7–13dp 圆角；保持品牌识别，深色模式也不改成黑色底。
- **状态点**：6dp；正常中性、warning、critical 三档；只配合文字出现，不单独承载语义。

### 6.6 动效

| 场景 | 规格 |
| --- | --- |
| 按下 | 100ms；卡片 scale .99 + ripple；按钮 scale .97 |
| 模式切换 | 下划线 240ms；卡片重排 320ms，spring(damping 1, response .35)，可被再次点击打断 |
| 弧线数值 | 500ms ease-out；从旧值到新值 |
| 定位高亮 | 300ms；1.02 倍 + 4dp 抬升；不弹跳 |
| 列表拖动 | 拖动时轻微抬起；其余项跟随；触感 CLOCK_TICK / LONG_PRESS |
| 更新星星 | 2.4s 呼吸；唯一常驻动画 |
| 减少动态 | 只保留淡入淡出；去掉位移、缩放、呼吸 |

### 6.7 无障碍

- 触控区 ≥ 48dp；开关、更多、重置卡 chip、筛选、返回/分享均为 48dp。
- 正文/标签对比度 ≥ 4.5:1；大数字 ≥ 3:1；深色按钮用 `onAction` 深字。
- 状态 = 圆点 + 文字；弧线有百分比；细条有数值；颜色不是唯一信号。
- 动态字体：字号跟随 sp；字体放大 1.3× 时简洁模式退回 1 列，完整分栏改为上下堆叠。
- TalkBack：卡片、健康标尺段、重置卡 chip、开关、筛选都有完整 contentDescription。
- 减少动态/透明度：不使用 blur；减少动态时只做淡入淡出。

## 7. 首页

### 7.1 结构

```
固定头部（44dp）
  左：凭证列表图标（48dp 触控）
  中：简洁 / 完整（纯文字 + 2dp 下划线，44dp 触控）
  右：设置图标 + 更新点（48dp 触控）
更新提示（28dp，仅有更新时出现）
状态行（34dp）
  “6 个账户 · 2 个需注意 · 20:04 同步” + 全部供应商下拉（30dp）
健康标尺（4dp）
卡片网格
```

- 头部固定；内容滚入时出现 1px hairline + 12dp 渐隐。
- 不加页面大标题；首屏优先出现数据。
- 下拉刷新保留；刷新中不整页闪，弧线数值平滑过渡。

### 7.2 状态行 / 筛选 / 健康标尺

- 状态行只让“N 个需注意”带颜色（warningText）；其余 muted。
- 筛选收成单个 pill「全部供应商 ▾」；点开是锚定菜单，列出供应商 + 数量；
  不换行、不堆 chip。
- 健康标尺是 4dp 高的分段条，每段对应一张卡；正常段中性，warning/critical 段用状态色。
  点段滚动到对应卡片，并给一次 300ms 的轻抬高亮。

### 7.3 简洁 / 完整

| 维度 | 简洁 | 完整 |
| --- | --- | --- |
| 列数 | 手机 2 列；600–839dp 3 列；≥840dp 4 列 | 手机 1 列；≥700dp 2 列 |
| 每卡 | 身份 + 1–2 个核心指标（弧线/金额） | 身份 + 主指标 + 2–3 条次级指标 + facts |
| 刷新 | 隐藏单卡刷新；失败卡才出现重试 | 保留单卡刷新 |
| 页脚 | 状态/重置/余额 | 更新时间 + chevron |
| 目标 | 扫一眼“有没有事” | 看清“差多少、什么时候重置” |

- 卡片高度由内容决定；相似元素（身份区、弧线、标签行、mini 行）在卡内保持统一行高与间距，
  从卡片顶部对齐。简洁模式用 `LazyVerticalStaggeredGrid` 瀑布流，避免相邻列因行数不同而显得
  参差；完整模式用 `LazyColumn`（≥700dp 时两列网格）。
- 模式选择持久化；默认沿用现有实现。
- 默认密度现状（已确认：保持现状）：全新安装（DataStore 为空）为 **简洁**；已有其他设置但没有密度字段的迁移用户为 **完整**；用户手动选择后持久化。建议保持这一现状，不做自适应默认。

  迷你条 3dp；页脚 11.5sp。

## 15. 风险与开放问题

### 15.1 风险

- **首页换网格**：`LazyStaggeredGrid` → `LazyVerticalGrid`（简洁）/`LazyColumn`（完整）
  会改变滚动/定位逻辑；健康标尺的 `animateToItemCentered` 需要适配。
- **完整模式信息密度**：去掉内部分割线后，行与行靠间距区分；如果 provider 字段很多
  （小米 API、New API），仍可能拥挤，需要在 P1 用真实数据复核。
- **深色主按钮**：高保真稿里白字在浅蓝上对比不足；实现按 `onAction` 修正。
- **组件重命名**：`Glass*` → `MyToken*` 是机械但面广的改动（约 20 个 Kotlin 文件 + 测试）；
  建议单独一个 PR，先重命名再改样式，避免 diff 混在一起难以 review。
- **测试断言**：大量 testTag/源码断言会随结构调整；需在同一 PR 更新，避免 CI 红。
- **设置抽屉**：当前设置/凭证列表在抽屉中；设计稿按页面画，抽屉场景要确认
  关闭按钮、1 列、底部安全区。
- **默认模式**：保持现有默认；如果产品希望新用户默认简洁，需要单独决策。

### 15.2 已确认的决定

1. **抽屉适配**：保留现有 edge drawer 结构；凭证列表与设置保持在抽屉内。
   - 列表页本身没有返回箭头，保持；设置页的返回箭头换成关闭“×”（系统返回也关闭抽屉）。
   - 抽屉宽度按 `min(屏宽 × 0.88, 420dp)`（390dp 手机约 343dp）；内容 1 列
     （当前代码在抽屉里强制 `Compact`）。
   - 底部 privacy / action 区加 `navigationBarsPadding`；不新增页面内 scrim。
   - 不改造成全屏路由。
2. **默认密度**：保持现状——全新安装（DataStore 为空）为简洁；已有其他设置但无密度
   字段的迁移用户为完整；用户手动选择后持久化；不做自适应默认。
3. **组件重命名**：`Glass*` / `LiquidGlassSurface` 在 P0 一并重命名为 `MyToken*`。
4. **历史趋势**：不做。
5. **设计稿入库**：三份高保真 HTML 已放入 `docs/design/`。

## 17. 实现备注

实现（2026-11-21，分支 `feature/android-visual-refresh`）与本文档的差异与补充：

1. **下次刷新时间**：`CredentialDetailScreen(nextRefreshAt = …)` 只在调用方提供时渲染
   `· 下次刷新 HH:mm`；当前应用状态没有排程刷新时间，因此详情页只显示更新时间。
2. **健康帮助入口**：已按确认移除；状态圆点 + 健康标尺承担解释，不再有独立帮助入口。
3. **§5.2 命名**：`LiquidGlassSurface` 不只是改为实色实现，而是在 P0 直接重命名为
   `MyTokenSurface`（与 §12.1 / §15.2 一致）；`Glass*` 组件同理。
4. **健康标尺触控**：每段触控区占满 48dp 高度（视觉条仍为 4dp），标尺右侧预留 132dp
   给筛选 pill，避免 pill 覆盖最后一段。
5. **加载骨架**：仅当 `Loading` 且没有缓存指标时显示静态骨架；有数据刷新时保留内容并
   显示「刷新中」，避免闪烁。
6. **供应商选择**：编辑页供应商为底部 sheet（2×4 磁贴）；选择立即生效，sheet 随后收起。
7. **详情页**：`DetailHero` 不含重试回调，失败时由底部主操作「立即刷新」承担重试；
   余额卡在「全部窗口」按币种重复构成条。
8. **删除的旧实现**：`ProviderCatalog.accentColor`、`ModelIdChipPalette`、
   `MyTokenPalette` 与 `MyTokenType` 的旧过渡别名均已删除；新增
   `DesignTokenLintTest` 阻止内联颜色/字号/半透明卡片表面回流。
9. **设计稿对齐（2026-11-21 复核）**：按 `docs/design/home-hifi.html` / `cards-spec.html` / `pages.html`
   逐项校准——顶栏汉堡菜单与齿轮更新点、28dp 更新提示、「状态行 34dp + 全宽健康标尺」两行结构、
   简洁卡居中弧线 + mini 行 + 两段式页脚、完整卡左 40% 弧线右 60% 指标、Command Code 构成条 + 图例、
   OpenCode/Routin facts、列表实心蓝色「添加」pill 与小号分节标签、编辑页纵向供应商磁贴与全宽取消、
   设置页 M 品牌块、详情页 88 环与窗口行排版。分节标题统一移到卡片外（11sp 大写字距、muted）。
10. **简洁卡节奏（2026-11-21 调整）**：放弃 288dp 固定高度；卡片高度随内容自适应，
    身份区（35dp 起）、弧线块、24dp 标签行、18dp mini 行仍保持统一行高与顶部节奏，
    页脚跟随内容。首页简洁模式改为 `LazyVerticalStaggeredGrid` 瀑布流，
    相邻列不再因行数不同而错位；完整模式与 `locateCard` 定位逻辑同步适配。
11. **第二轮设计对齐（2026-11-21）**：重置卡 chip 改为设计稿的浅底 hairline + 叠卡图标
    （简洁 17dp 仅数字、完整 19dp「重置卡 N」）；简洁 chip 紧贴弧线标签，完整主指标 chip
    换行到标签下方，窗口 chip 紧跟窗口标签。供应商 logo 保持设计稿的 24dp / 28dp
    （曾试过 34/36，视觉过重已回退）；健康标尺到卡片区间距收到 14dp；凭证列表入口改为
    两长一短三横线；CommandCode 简洁卡去掉余额行；DeepSeek / 小米余额构成与 facts
    行距加大。
12. **设计稿同步（2026-11-21）**：`docs/design/` 下三份 HTML 已回写本轮实现——简洁卡
    瀑布流、重置卡 chip 尺寸与位置（详情页 chip 同步为 19px）、CommandCode 简洁卡去余额行、
    余额卡图例/facts 行距；`docs/design/README.md` 记录了同步规则。
13. **设置页与抽屉手柄（2026-11-21）**：设置分组间距 18dp、资料卡距页头 6dp；刷新/通知行
    补齐设计稿说明文案；资料卡品牌位改用产品 logo（`mytoken_brand_logo`）；「关于」改为
    常显四行（版本 / 检查更新 / 更新日志 / 更新源与令牌），下载/安装动作只在需要时出现在
    行下方；抽屉手柄竖条在面板边框与 16dp 页边距之间居中（距边框 8dp）。
14. **详情页与下拉菜单（2026-11-21）**：Hero 默认渲染周期最短的进度指标（按
    `windowStart/windowEnd` 时长，缺失时按 id/标签推断）；「全部窗口」固定按
    5 小时 → 周 → 月排序（未知周期居中、月最后），重置卡按到期日拆成
    `MM-dd HH:mm` 日期 chip；「账户与模型」移除分组倍率，允许模型默认最多两行，
    超出部分在第三行显示「查看更多」，展开后可「收起」；「配置」官网地址完整展示并允许换行（插入零宽空格提供断点，
    `LineBreak.Paragraph`，不省略）。详情页右上角菜单与「全部供应商」筛选统一改用
    `core-ui` 的 `MyTokenDropdownMenu`（实色 surface、hairline、12dp 圆角、12dp 投影、
    48dp 行高、选中勾）。设计稿 `pages.html` 已同步上述详情页样式。

    `MyTokenThemeTokens.colors.canvas`，消除 M3 默认 surfaceContainer 的粉紫底色；
    模板风格改为四等分「上图下字」选项（不显示模式副标题）；展示字段改为可点击胶囊
    （再点取消），默认一行 + 「更多」，展开后可「收起」，四项以内直接全部展示；
    复制/保存/分享收进右上角图标（48dp 触控），操作结果改用 Toast，移除内联状态行。
