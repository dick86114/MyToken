# 凭证卡片简洁 / 完整模式设计

## 1. 背景

菜单栏弹层里的凭证卡片目前一律展示完整用量。不同供应商字段量和排版差异很大：小米 API 有八格账户/Token，GLM 还有调用量和活跃度，New API 有额度、多窗口消耗和请求活动。很多人打开弹层只想确认「还能不能用、什么时候重置」，完整卡片偏吵，凭证一多弹层也偏长。

菜单栏已经能按凭证挑选一个指标；卡片仍缺少全局的信息密度选择。

## 2. 已确认的产品决策

1. 只有全局简洁 / 完整两种模式，不对单张卡片分别设置。
2. 完整模式保持现有卡片内容，唯一例外是不再显示分组倍率。
3. 简洁模式使用各供应商写死的布局，不提供用户勾选字段。
4. 弹层顶栏设置按钮左侧放 `简洁 | 完整` 胶囊分段（方案 A），设置 → 通用里放同一项。
5. 两处开关绑定同一个设置，切换后弹层卡片立刻变化。
6. 全新安装默认简洁；升级用户若从未写过该键，维持完整。
7. 本轮只做 macOS。Android、官网和迁移协议不同步该设置。

## 3. 目标

- 让多数用户在弹层里只看到各供应商最常用的用量。
- 让需要细节的用户能一眼切到完整模式，不必只靠设置页发现。
- 保持各供应商现有完整布局和指标语义，不收成一张通用网格。
- 升级不改变老用户当前看到的完整卡片（分组倍率除外）。

## 4. 非目标

- 不按凭证、不按供应商类型提供可编辑的简洁字段配置。
- 不把简洁模式做成「把完整卡藏几格」的通用过滤器。
- 不改变菜单栏指标、提醒规则、刷新、分享卡片内容。
- 不在本轮改 Android 首页卡片、小组件或传输 schema。
- 不压缩卡片头里的名称、供应商 · 套餐、分享和刷新。

## 5. 方案选择

曾考虑三种做法：全局模式 + 供应商写死简洁布局；默认配置再加用户勾选；每张卡自己折叠。采用第一种。用户勾选会拆掉小米、GLM、New API 等已排好的结构，设置也会和菜单栏指标、提醒叠在一起。每卡折叠和「整个弹层统一密度」的目标不一致。

## 6. 界面

### 6.1 弹层顶栏

在 `UsagePopoverView` 顶栏右侧、设置齿轮左侧增加高度 30pt 的胶囊分段，视觉对齐现有齿轮按钮和左侧版本胶囊：

- 选项文案：`简洁`、`完整`
- 选中段白底、未选中段透明
- 外框圆角 8pt，与齿轮同一套浅填充和描边
- 不放进会滚动的「账户用量」标题行，也不放底栏

### 6.2 设置 → 通用

新增「显示」小节，或并入现有通用页，提供同一套 `简洁 / 完整` 选择。说明文案：

> 简洁模式只保留各供应商最常用的用量信息。

### 6.3 卡片头

两种模式都保留：显示名、供应商 · 套餐、分享、刷新、失败指示。

两种模式都不显示分组倍率（当前主要出现在 Routin 订阅卡头部，例如「默认分组 ×2」）。无障碍文案同步去掉，避免仍被读出。

简洁模式不显示订阅开始 / 结束日期。完整模式订阅日期保持现状。

## 7. 简洁模式内容

额度类单元格统一为：标题、百分比、进度条、重置时刻。重置时刻沿用现有 `UsageFormatter.resetTime`：当天 `HH:mm`，跨天 `MM-dd HH:mm`，UI 前缀为「重置」。不显示已用 / 限额，也不显示剩余时长。

| 供应商 | 简洁模式显示 | 不显示 |
| --- | --- | --- |
| Routin 订阅 | 5 小时、周，各带进度和重置时刻 | 分组倍率 |
| Routin Token 包 | Token 进度和重置时刻（若有窗口） | 分组倍率 |
| DeepSeek | 账户余额 | 账户状态 |
| 小米 API | 账户余额 | 累计消费、现金/赠送、历史消耗、Token 拆分 |
| 小米套餐 | 套餐总量进度（百分比 + 条） | 补偿 Credits、订阅状态、重置时刻 |
| GLM | 5 小时、周，各带进度和重置时刻 | 模型调用量、MCP、活跃度 |
| 火山 Agent / Coding | 5 小时、周、月，各带进度和重置时刻 | 已用/限额/剩余数量等明细行 |
| New API | 今日 Token、24 小时 Token、7 天 Token、30 天 Token，2×2 数字格 | 账户额度、消费金额、RPM/TPM、累计请求 |
| Command Code | 5 小时、周、月，各带进度和重置时刻 | 累计请求、已购/免费剩余 |

火山和 Command Code 的月度格仍单独一行，避免三块挤在同一行。New API 四项是数字，没有进度条。DeepSeek 和小米 API 的余额保持现有余额数字样式，只是旁边不再放第二项。

完整模式除分组倍率外，字段、顺序、文案和现有实现一致。

## 8. 数据模型

```swift
enum UsageCardDensity: String, Codable, Equatable, Sendable, CaseIterable {
    case compact
    case full
}
```

`AppSettings` 增加 `usageCardDensity`，写入 UserDefaults，键名 `usageCardDensity`。

弹层分段和通用设置都读写该属性。

### 8.1 新装与升级

初始化时：

1. 若 UserDefaults 已有 `usageCardDensity`，使用该值。
2. 否则若 UserDefaults 中已存在 `refreshMinutes`、`displayOrder.v1`、`selectedCredentialIDs`、`availableCredentialIDs`、`credentialUsagePreferences.v1` 任一键，视为升级用户，设为 `full` 并写回。
3. 否则视为全新安装，设为 `compact` 并写回。

判断升级时必须在同一次 `AppSettings` 初始化里、在可能回写其他默认值之前读取这些旧键，避免新装先写入默认刷新间隔后再被当成升级。

### 8.2 备份

`ConfigurationBackupSettings` 增加 `usageCardDensity`。导出写入当前值。旧备份缺少该字段时按 `full` 导入，避免把老用户配置收成简洁。

不加入 Android / macOS 互传 schema。

## 9. 渲染

`UsageRowView` 从 `AppSettings.usageCardDensity` 取密度，传给各供应商卡片视图。不要做「按 metricID 白名单过滤后再塞进通用网格」的通用层。

额度简洁格抽成共用展示，供 Routin、GLM、火山、Command Code 等复用，避免每家各写一套百分比 + 条 + 重置。供应商仍决定显示哪些指标、几列、月度是否独占一行。

New API 简洁模式只渲染四个 Token 数字格。小米 API 简洁模式只渲染账户余额。小米套餐只用套餐总量进度条。

`CommandCodeUsageMetricsDisplayMode` 的 `card` / `details` 是详情页和卡片的既有差异，不要和全局密度混成同一个枚举。全局简洁模式作用在弹层卡片上。

## 10. 测试

- `AppSettings`：新装默认简洁；已有旧键、没有密度键时为完整；已写入的值优先；备份缺字段时导入为完整。
- 弹层和通用设置读写同一属性，切换后卡片密度变化。
- 各供应商简洁布局只包含第 7 节列出的字段；完整模式除分组倍率外与现网一致。
- 分组倍率在两种密度下都不出现在卡片和无障碍文案中。
- 不改 Android 测试范围。

## 11. 范围

本轮只改 macOS 弹层卡片、通用设置、`AppSettings` 和配置备份。不改菜单栏按钮本身、分享图、提醒，以及 Android / 官网。
